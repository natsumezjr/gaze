# 桥接层消息协议

眼动后端通过 WebSocket 与任意前端（Node.js、Unity、Web 等）通信时，统一采用本协议。每条消息为**一行 JSON**，格式：

```json
{ "event": "事件名", "payload": { ... } }
```

- `event`：字符串，与 [project/events/event_types.py](project/events/event_types.py) 中的事件名一致。
- `payload`：对象，随事件不同而不同；无参数时可为 `{}`。

---

## 一、服务端 → 前端（Python 推送）

后端在发生以下事件时，会向所有已连接的 WebSocket 客户端推送对应消息。

### 1. calibration_start_request

请求开始或继续标定。

```json
{
  "event": "calibration_start_request",
  "payload": { "frame_id": 1234567890123456 }
}
```

### 2. rough_gaze_update

当前帧粗略注视点（标定时的蓝点/动画用）。

```json
{
  "event": "rough_gaze_update",
  "payload": {
    "frame_id": 1234567890123456,
    "eye_type": "left",
    "intersection": { "x": 960.5, "y": 540.2 }
  }
}
```

### 3. gaze_point_update

在界面上显示一个视线点（如拟合后的蓝点）。

```json
{
  "event": "gaze_point_update",
  "payload": {
    "point": { "x": 960.5, "y": 540.2 },
    "color": "#0000FF"
  }
}
```

### 4. request_calibration_ui_close

请求关闭标定 UI（如标定完成或后端请求关闭）。

```json
{
  "event": "request_calibration_ui_close",
  "payload": {}
}
```

### 5. system_stop

系统停止。

```json
{
  "event": "system_stop",
  "payload": {}
}
```

---

## 二、前端 → 服务端（客户端发送）

前端按以下格式发送消息，后端解析后注入 `CALLBACK_MANAGER`，与 Tk 等进程内前端行为一致。

### 1. calibration_point_submit

用户确认一个标定点。

```json
{
  "event": "calibration_point_submit",
  "payload": {
    "frame_id": 1234567890123456,
    "eye_type": "left",
    "target_pixel": { "x": 100, "y": 200 },
    "background_color": "black"
  }
}
```

### 2. calibration_complete

标定全部完成。

```json
{
  "event": "calibration_complete",
  "payload": {
    "calibration_result": { "total_points": 27 }
  }
}
```

---

## 三、连接与配置

- **默认地址**：`ws://<host>:<port>`，例如 `ws://localhost:8765`。
- **配置**：在 [project/config/settings.py](project/config/settings.py) 中设置 `BRIDGE_ENABLED`、`BRIDGE_HOST`、`BRIDGE_PORT`；仅当 `BRIDGE_ENABLED=True` 时启动桥接服务。
- **并发**：多个客户端可同时连接，服务端推送会广播给所有连接；任一客户端发送的 `calibration_point_submit` / `calibration_complete` 会进入同一套后端逻辑（与 Tk 共享）。
