# 调研步骤与规范

## 1. 第一周
- 主要任务：整体了解`structure.md`中项目的整体流程和各模块分工。
- 要求：每个人需通读结构文档。

## 2. 第二周 ~ 倒数第二周
- 主要任务：对`structure`中涉及的各模块进行定量的算法调研。
- 要求：
  - 每个人查阅文献、对比不同算法（如Python库选择、系统误差分析等），形成调研结论。
  - 调研结果需以文档形式写在各自的`result`文件中，内容包括：
    1. 对比各类算法的优劣（如精度、速度、易用性、依赖库等）
    2. 结合实际需求，决定最终采用的算法，并说明理由
  - 每周例会时，大家共同讨论、修改完善`structure.md`，确保流程和接口不断优化。

## 3. 倒数第二周
- 主要任务：根据前期调研和讨论，统一并细化各模块之间的接口定义。
- 要求：
  - 明确输入输出格式、数据类型、调用方式等
  - 在`structure.md`和接口文档中补充接口说明

## 4. 最后一周
- 主要任务：根据已定接口和算法，正式开始代码实现。
- 要求：
  - 各自负责模块的代码开发
  - 保证接口对接顺畅，及时沟通问题

---

## 算法调研规范

1. **前提：**
   - 在对整体流程有清楚认知的基础上，针对所负责模块进行算法调研。

2. **调研步骤：**
   1. 对比多种可选算法的优劣（如不同Python库、系统误差、性能、易用性等），形成表格或要点总结。
   2. 结合实际需求和团队讨论，决定最终采用的算法，并在`result`文档中明确记录选择理由。

3. **调研结果文档要求：**
   - 结构清晰，结论明确
   - 包含对比分析、最终选择、理由说明
   - 便于后续查阅和复用
